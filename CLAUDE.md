# Yap — Claude's operating manual

A tiny voice and chat app: **text channels + voice channels, nothing else.** For a group of
friends. Free, always-on hosting on Cloudflare; voice is peer-to-peer Opus at
higher-than-Discord bitrates. Open source (MIT since 2026-10-12; AGPL-3.0 before); anyone can run their own
server (`SELF_HOSTING.md`).

**If `private/README.md` exists, read it first:** the maintainer's own notes
(their server, to-dos, history). `private/` is gitignored and never published.

- **Server:** Cloudflare Worker + two SQLite-backed Durable Objects, `Hub` (everything) and `Media` (stored files) — Workers **Free** plan.
- **Web client:** vanilla JS + CSS in `web/`, no build step, served as static assets by the same Worker.
- **Desktop client:** `desktop/` — Rust (egui, webrtc-rs, cpal, pure-Rust Opus, RNNoise, WebRTC's AEC3 echo cancellation via `sonora`, global push-to-talk, mute, deafen and push-to-mute keys; `yap --remote mute|deafen|…` on macOS/Linux over a private Unix socket). Builds for macOS, Linux and Windows from a Mac (`desktop/scripts/build-cross.sh`; binaries in `desktop/target/dist/`, not in git). See `desktop/README.md`. **Never Electron** — a project rule.
- **SwiftUI client:** `apple/` (iOS + macOS, YapKit package) — see `apple/README.md`. iPhone updates come through TestFlight. In a call the iPhone shows a Win98-style Live Activity (Lock Screen + Dynamic Island: who's in, Mute, Deafen, a × that asks "Leave …?"; `YapLive/`, `Yap/App/LiveCall.swift`). Draw and Space are the web app in an in-app web view, opened with a one-time sign-in pass and `#…&embed=1` (no web header; `web/js/theme.js`).
- **Look** (Settings › Look, per device): one look, **Windows 98 / AIM** (`web/style.css`), in dark "Charcoal" (default), light "Windows Standard", or Match system. `js/theme.js` sets light/dark before first paint (`js/app/look.js` after). A skin saved by an older version (web `settings.skin` apple/arch, which older iPhone/Mac apps also write into their web view; the desktop's `"skin"`; the Apple app's `yap.skin`) is ignored and dropped. The Apple and Arch skins were removed on 2026-10-10 (Decision log). Windows 98 keeps its instant/stepped motion on purpose. Win98 look: — grey bevelled windows on a teal desktop, navy title bars (always active on both windows — the focus swap made the sidebar's bar flash), white sunken wells, Tahoma, square corners, AIM chat lines (`Name: text`; you red, others blue), buddy list, property-sheet Settings. Dark "Charcoal" is the default; light is "Windows Standard". Same tokens in all three clients (`web/style.css`, desktop theme, `apple/Yap/App/Theme.swift`).
- **Updates:** web pages update themselves after a deploy — CSS swaps in place, anything else reloads when it's safe (`tools/stamp.mjs` → `web/js/build.js` + `worker/build.ts`, generated by install/dev/check/deploy and never committed; PROTOCOL.md › Updates). Desktop apps: signed click-to-update from `/downloads/latest.json` (each deployment's own Ed25519 key; builds without a key don't self-update — `desktop/README.md`).
- **What's new highlights:** `web/changelog.json › highlights` is a curated list (date, emoji, title, text, where) shown at the top of `/changelog` while it's from the past 7 days — add the big things there when you release them.
- **Versioning:** you (Claude) own it. Put user-facing `Changelog: …` lines in commit bodies; `npm run release ["Title"]` picks the next version from commits since the last tag, updates `web/changelog.json` + `package.json`, commits and tags (only from a clean tree); then deploy. The release commit carries no trailers unless you pass them: `npm run release -- "Title" --trailer "Co-Authored-By: …" --trailer "Claude-Session: …"` (or `RELEASE_TRAILERS`, one per line). The changelog page is `/changelog` (subtle link at the bottom of the sidebar).
- Invite key: the main link `https://<server>/#key=<key>`. Worker secret `YAP_KEY` is only the first one: the owner resets it (Settings › Invite › Reset main link…, `invite.resetMain`; or `POST /api/admin/main-key`, `DELETE` goes back to `YAP_KEY`) and the Hub keeps it in meta `main_key` (in backups). A socket with a wrong or old key may only send `hello { token }` (else 4003 "wrong invite key"), so signed-in devices are never stranded and pick up `ready.key`/`key`. Members also make **personal invite links** (`yi_…`, Settings › Invite; only a hash is stored, revocable, attributed in the waiting room); the Worker checks them with the Hub (`checkInvite`, cached 60 s). Members receive the main key in `ready`, so revoking an invite never locks anyone out.
- Sidebar **Places** links live in the Hub (`links` table, editable in the app; a board link is seeded and only shows on servers with a board).
- **Mod log** (`mod_log`): who let in/banned/made invites/etc., never message text; everyone can read it (Settings › Owner & mods).
- **Each deployment's settings** live in its own `wrangler.jsonc` (gitignored; template `wrangler.example.jsonc`) and Worker secrets: domain, `PUBLIC_URL`, optional Minecraft status and board (`worker/settings.ts`). Nothing about any one server is in the code.
- **GIFs:** KLIPY picker; Worker secret `KLIPY_KEY` (a free KLIPY app key; Testing mode = 100 requests/hour for the whole server). KLIPY's terms forbid proxying — see PROTOCOL.md › GIFs.
- **Standard emojis:** `web/emoji-data.json` (1,898 emojis ≤ Emoji 15.1, Slack/Discord-style shortcodes), generated by `tools/build-emoji-data.mjs` from the `emojibase-data` devDependency; shown in the system emoji font.
- **Custom emojis:** unlimited count, ≤ 512 KB each; bytes in the `Media` Durable Object (its own 1 GB), records in `Hub`.
- **Board (optional):** another Worker of the server owner's, bound as `BOARD` (a service binding), served same-origin at `/board` with the paths it uses listed in `BOARD_PATHS` (`worker/board.ts`, `worker/settings.ts`). Yap draws live pointers over it (`web/js/cursors.js`, anchored to `[data-lane]` columns and `[data-id]` cards). Opens in the main pane, so voice keeps going. Tests use a stand-in board (`test/fixtures/board/`).
- **Moderation:** strangers wait in a waiting room until the owner or a mod lets them in (only they get `join.request`/`ready.pending` and a push, "invited by …"; everyone meets the newcomer in `join.resolved.user`); owner/mods ban, delete and reset passwords; per-session rate limits. Owner = whoever holds the admin key (`owner.claim`).
- **Places (main-pane views, voice keeps going):** the optional board, **Draw** (shared live drawing board + gallery, `web/js/draw.js`; WigglyPaint-style: rendered at 640×400 with hard pixel edges, wiggle frames, Save = PNG, GIF = looping animated GIF via `web/js/gif.js` (no library); three shared layers (strokes carry `l`; hiding one is per person; PROTOCOL.md › Draw layers); Clear archives the page as a GIF, then clears one layer (`draw.wipe`) or the page), **Watch** (watch YouTube together: one shared player state in the Hub, `web/js/watch.js`; a youtube-nocookie iframe driven by postMessage only, theater seats under the video, your own volume, a mini player that keeps going while you browse; PROTOCOL.md › Watch together), **Space** (top-down world with CS:GO-style radar; rooms are voice zones — "This room only" by default; nine rooms incl. Music (WebAudio floor piano + drums), a Pond and the Gallery (Draw's saved drawings framed on the walls, 12 to a wall, live via `draw.gallery`/`drawing`, a big viewer so GIFs play), a race track round the edge; football, tag, water balloons, laps and fire/water effects over the `space.game` relay, nothing stored; `web/js/space.js` + `space-map.js`/`space-art.js`/`space-sound.js`, PROTOCOL.md › Space).
- **Reactions** on messages (`react` / `reaction`), @mention highlights + unread-mention badges; **doodle reactions** (`<d:mediaId>`, a 48×48 wiggly pixel doodle from `web/js/doodle.js`, `POST /api/doodle`; one per person per message; erased with the reaction).
- **Extras (v0.36, PROTOCOL.md › Extras):** spoilers `||…||`; polls (`send.poll`, `poll.vote`, `poll_votes`); `/roll` `/flip` rolled **by the server** (`messages.extra`, can't be edited); soundboard + join chimes (`sounds` table, WAV only, the Worker measures loudness and caps `gain`; clients add their own volume, a limiter and ≤ 2 clips — `web/js/sounds.js`, `soundboard.js`); AIM-style away messages (`users.away`, the `away` auto-reply to whoever mentions you); quiet hours (`users.quiet`, checked in `deliver()`); hang reminders (`hangs`, a Durable Object **alarm** fires one push to whoever was free); catch up (`unread.counts`, "New since" divider); media shelf (`shelf`); Save to Personal (a `replyTo` bookmark across channels); quick switcher (Ctrl/⌘+K, `web/js/switcher.js`; search is Ctrl/⌘+Shift+F); YouTube links → Watch together.
- **Messages:** up to 40,000 characters (long ones fold behind "Show more"); edit your own (`edit`/`edited`; old versions in `message_edits` until deleted); **replies** (`replyTo` → `message.reply`, counts as a mention); pictures (`image`, `/api/image`, ≤ 1.9 MB = one Media row); GIF favorites (local); emoji skin tones (5th field in `emoji-data.json`).
- **Deleting a message erases it** (text, GIF, picture bytes via `media_trash` → `emptyTrash()`, reactions, edits); the row stays as a tombstone.
- **No presence, on purpose:** no online/offline, last seen or member column; sessions are only visible in voice or on a shared view (`visible()` in `worker/attachment.ts`); the member list is a People sheet behind the header button.
- **Personal space** (`p_<uid>`): only you; optionally end-to-end encrypted with a passcode (`web/js/vault.js`, `users.space_wrap`, `e1:` notes, `/api/blob` for sealed pictures; turning it on seals older notes via `personal.plain`/`personal.seal`).
- **Search** (header 🔍 or Ctrl/⌘+Shift+F; `search` — LIKE scan, words + `from:` + `has:`; encrypted notes are searched on the device) and **pins** (`pin`/`pins`, `messages.pinned_at`, ≤ 50 per channel). Jumping to an old message loads older pages until it's there (`loadUntil`).
- **Voice relay:** `/api/ice` adds a TURN relay when one is configured — a fixed login (`TURN_URLS`/`TURN_USERNAME`/`TURN_CREDENTIAL`, e.g. ExpressTURN's free no-card plan, so no card on Cloudflare) or Cloudflare TURN (`TURN_KEY_ID`/`TURN_KEY_API_TOKEN`); Settings › Voice › "Hide my IP address in calls" forces relay-only (`iceTransportPolicy: 'relay'`) and is disabled until the relay exists.
- **When's good** (Places): a weekly when2meet (`web/js/when.js`, `when_slots`, half-hour slots since the epoch; old weeks drop off).
- **Privacy page:** `/privacy` (`web/privacy.html`), linked from the sidebar. Update it whenever what's stored or shared changes.
- **Screen sharing** (in voice, every client; PROTOCOL.md › Screen sharing): `voice.state.screen` → a LIVE badge, or the sharer's name › Watch screen; video goes peer to peer only to people who ask (`signal {screen: 'want'|'stop'}`); H.264 constrained baseline is the codec every client offers. Sharer: Watching: …, Smooth/Sharp/Max and Share sound live, Share something else, Stop sharing. Viewer: fitted, its own sound volume per person, Full screen, Pop out, Connecting… / paused (3 s without a frame) / stopped (closes after 2 s). Web: `web/js/screen.js` + `voice.js`. Desktop: shares on macOS (ScreenCaptureKit through Apple's picker on 14+, hardware H.264), Windows (Graphics Capture) and Linux X11 (not Wayland yet), OpenH264 elsewhere (`desktop/README.md`). iPhone/Mac app: watches everywhere, shares from the Mac (ScreenCaptureKit) and from iPhone/iPad (the ReplayKit extension `apple/YapBroadcast`, pictures over an App Group Unix socket into the app's encoder), picture only (stasel/WebRTC can't put other audio on a track) (`apple/README.md` › Screen sharing).
- **Voice extras:** per-channel quality (`channels.bitrate`), per-person volume to 200% (WebAudio gain + limiter), noise suppression = RNNoise in the browser too (`web/vendor/noise`, CSP `'wasm-unsafe-eval'`; the browser's own filter only where it can't run; one switch), OBS output (`/obs`: played the way VDO.Ninja's OBS view does, each voice straight from its own element with the browser's jitter buffer, started again if it pauses; an inaudible −60 dBFS 20 Hz tone only while nobody is heard (`&keepalive=0` turns it off), so OBS's browser never stops capturing in a pause; listen-only device tokens, `devices.scope`; it listens only while its account is in that channel or for 5 minutes after it left — meta `obs_grace:<uid>:<channel>` + the Durable Object alarm, shared with hangs through `Hub.armAlarm` — and every app leaves it out of the channel and its chimes, showing the account greyed meanwhile); the transmit gate on the audio thread (`web/js/gate-worklet.js`: hysteresis, hold, fades, push-to-talk tail, 40 ms pre-roll, adaptive noise floor); Settings › Voice › Hear yourself (an Opus loopback at the call bitrate); calls survive socket drops and deploys (`ready.resumeKey`, `voice.join {resume, prev, proof}` — PROTOCOL.md › Voice › Keeping calls across reconnects); quiet per-person connection hints; mic/device/AudioContext recovery with fail-open.
- **Browser pushes:** Web Push (`worker/webpush.ts`, `web/sw.js`, secret `VAPID_PRIVATE_JWK`, made by `tools/make-vapid.mjs`), alongside ntfy.
- **Uploads** need `sid` + `ut` (the per-connection `uploadToken` from `ready`).
- **Accounts:** name + password (8–128 characters, since 2026-10-11). Guessable ones are refused (`worker/auth.ts`, `weak_pin`): the ~10,800 most common of 8+ characters (`worker/common-passwords.ts`, built by `tools/build-common-passwords.mjs` from SecLists, MIT), your own name, one thing repeated, keyboard rows and counting. Older accounts may still have a 6-digit PIN (`users.secret_kind = 'pin'`): it signs in until they set a password; nothing new can be a PIN. `users.weak_secret` 1 = should be replaced, 2 = a temporary password from a reset → `ready.weakPin` + `ready.weakReason` → one "Choose a password" prompt per device. Resets hand out three words + two digits (`worker/words.ts`). The wire still says `pin`; new sign-ins alert your other devices (`signin.alert`); Settings › Account › Your devices lists/revokes device tokens (`devices.label` from the User-Agent). The pre-PIN uid-only sign-in is gone (`pin_required`); a PIN-less account gets in through an owner/mod PIN reset.
- **Security:** passwords (and old PINs) hashed with peppered PBKDF2-100k (`PIN_PEPPER` secret — keep a copy: a restore needs the same one), lockouts, a waiting room only the owner and mods open, rate limits (per session in the Hub, per IP via the `PER_IP` binding), invite key never in URLs, CSP + security headers (`web/_headers`; the board page gets a hash-based CSP from the Worker). Outsider floods still need a Cloudflare WAF rate-limit rule in front (SECURITY.md).
- **Pings & pushes:** 📣 ping button and @mentions chime for everyone online; phone pushes go through **ntfy** (each person gets a private topic; `worker/notify.ts`; `NTFY_SERVER`/`NTFY_TOKEN` optional secrets) and **browser pushes** via Web Push (`worker/webpush.ts`, no library; `web/sw.js`; secret `VAPID_PRIVATE_JWK`).
- **Avatars:** `POST /api/avatar` → Media store, `User.avatar`.
- **Minecraft (optional):** a sidebar status for the server in `MINECRAFT_SERVER` ("host:port"), via Server List Ping from the Worker (`worker/minecraft.ts`, `connect()` TCP).
- **Backups:** Cloudflare replicates + 30-day point-in-time recovery; plus `tools/backup.mjs`, a full export to `backups/` (gitignored) — daily on a Mac via `tools/install-backup.sh`. Admin API: Worker secret `ADMIN_KEY`; the tools find the server and key as `tools/instance.mjs` says. See PROTOCOL.md › Backups.

`npm run test:all` sets all of this up itself. Running the protocol test by hand needs the test server started with
`--var NTFY_SERVER:http://127.0.0.1:8790` (pushes hit the test's fake ntfy, which listens on `YAP_TEST_NTFY_PORT`,
default 8790), `--var TEST_HANGS:1` (a hang can start a second from now, so the alarm is tested end to end) and
`--var TEST_OBS_GRACE:4` (an OBS link keeps listening 4 s, not 5 minutes, after its account left; the OBS tests need it), `--var TEST_PINS:1` (tests only: `POST /api/admin/test-pin?uid=&pin=` gives an account an old 6-digit PIN; 404 without it; every suite signs up with the made-up password `correct-horse-582039`), `--var VAPID_PRIVATE_JWK:$(node tools/make-vapid.mjs)` (the browser-push test; its fake push service listens on
`YAP_TEST_PUSH_PORT`, default 8791), on a fresh `--persist-to` for a clean run.

## Conventions
- Protocol changes: edit `worker/protocol.ts` **and** `PROTOCOL.md` together; bump `PROTOCOL_VERSION` only for breaking changes.
- Client JS: ES modules, no framework, no bundler, no CDN (works offline / embeddable). Escape every user string with `esc()` before `innerHTML`.
- Server state that must survive hibernation goes in the socket attachment (≤ 2 KB) or SQLite — never only in instance fields (`lastTs` is a cache re-derived from SQLite).
- Free-plan budget: 100k requests/day (incoming WebSocket messages count 20:1), 100k row writes/day, 5 GB. Nothing per-audio-frame may touch the server.

## Guardrails
**Production data (real friends' messages):**
- `MIGRATIONS` in `worker/schema.ts` is **append-only**. Never edit a shipped migration; never drop/rename columns. `npm run test:migrations` upgrades databases from every older version.
- **Deleted messages are erased** (2026-10-05: "dont save deleted posts") — that's the one hard delete, and only of what the person deleted. Everything else stays soft (`deleted_at`, `archived_at`); never erase anything else without asking.
- Before changing the schema or any persisted shape, audit every reader/writer in `worker/hub.ts` and `worker/hub-*.ts`.

**Untested surfaces — call out "Please test this manually":**
- Voice across real networks (CGNAT/cellular may need TURN; tests only cover localhost).
- Safari / iOS / Firefox voice (tests run Chromium only), output-device picking, Bluetooth headsets.
- Echo cancellation / noise suppression quality (the desktop's AEC3 was only measured offline and in an echo loop: real speakers on macOS, Windows and Linux), push-to-talk feel, notifications.
- Round 10's feel: the push-to-talk click and double-tap latch, the "You're muted" reminder with a real mic, global keys on each OS and Wayland, `yap --remote` from a Stream Deck, Ctrl/⌘+scroll on rows, Space panning on headphones, the shared-media dip, the own-connection hint on a lossy uplink.
- RED on real lossy networks and Safari/Firefox (measured through the impairment proxy with Chromium only), the call report's clipboard on each OS, the iPhone's Mic mode picker (needs a real call on a device).
- iPhone calls with the screen off (interruptions, route and network changes while locked), iPhone/iPad screen broadcasts (ReplayKit doesn't run in the simulator), the desktop's Apple screen picker, and the call's Live Activity on a phone (its Dynamic Island never shows in simulator screenshots; its buttons from the Lock Screen).

## Code map
- **Worker:** `worker/index.ts` routes requests: `access.ts` (the invite key), `uploads.ts` (upload routes, serving stored files), `admin.ts` (`/api/admin/*`), `board.ts` (the optional board), `ice.ts` (STUN/TURN), `objects.ts` (the two Durable Objects' stubs).
- **Hub:** `worker/hub.ts` is the `Hub` Durable Object: lifecycle and the message dispatch, sessions, voice, views, uploads, queries, sending, rate limits, and the Worker's RPC (one-line delegations). Its features are functions of `hub: HubHost` in `hub-messages.ts`, `hub-accounts.ts`, `hub-admin.ts`, `hub-pushes.ts`, `hub-extras.ts`, `hub-watch.ts`, `hub-draw.ts`, `hub-space.ts` and `hub-backup.ts`; `hub-host.ts` says exactly which Hub members they may use (PATTERNS.md › A Durable Object in feature modules).
- **Server, the rest:** `schema.ts` (migrations), `rows.ts` (rows → wire shapes), `attachment.ts` (per-socket state), `validate.ts` (checks on what clients send), `extras.ts` (pure rules: dice, quiet hours, WAV loudness), `auth.ts`, `notify.ts`, `webpush.ts`, `encoding.ts`, `media.ts` (the `Media` object), `protocol.ts` (wire types), `settings.ts` (this server's vars).
- **Web:** `web/js/app.js` is the entry (boot, `handle()` for server messages, `bindUi()`, `onClick()`); `web/js/app/` holds the page's parts (`state.js` — state and the socket, a leaf — then `ui`, `look`, `uploads`, `updates`, `push`, `places`, `voice-ui`, `sidebar`, `messages`, `chat`, `composer`, `people`, `account`, `personal`, `search`, `extras`, `settings-ui`); `web/js/*.js` are self-contained widgets (`voice.js`, `gate-worklet.js`, `draw.js`, `space*.js`, `watch.js`, `when.js`, `vault.js`, `emoji.js`, `gifs.js`, …).
