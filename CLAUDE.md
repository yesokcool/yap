# Yap — Claude's operating manual

A tiny voice and chat app: **text channels + voice channels, nothing else.** For a group of
friends. Free, always-on hosting on Cloudflare; voice is peer-to-peer Opus at
higher-than-Discord bitrates. Open source (MIT since 2026-10-12; AGPL-3.0 before); anyone can run their own
server (`SELF_HOSTING.md`).

**If `private/README.md` exists, read it first:** the maintainer's own notes
(their server, to-dos, history). `private/` is gitignored and never published.

- **Server:** Cloudflare Worker + two SQLite-backed Durable Objects, `Hub` (everything) and `Media` (stored files) — Workers **Free** plan.
- **Desktop client:** `desktop/` — Rust (egui, webrtc-rs). Builds for macOS, Linux and Windows from a Mac (`desktop/scripts/build-cross.sh`; binaries in `desktop/target/dist/`, not in git). See `desktop/README.md`. **Never Electron** — a project rule.
- **SwiftUI client:** `apple/` (iOS + macOS, YapKit package) — see `apple/README.md`. iPhone updates come through TestFlight. Draw and Space are the web app in an in-app web view, opened with a one-time sign-in pass and `#…&embed=1` (no web header; `web/js/theme.js`).
- **Look** (Settings › Look, per device): one look, **Windows 98 / AIM** (`web/style.css`), in dark "Charcoal" (default), light "Windows Standard", or Match system; the same tokens in all three clients (`web/style.css`, desktop theme, `apple/Yap/App/Theme.swift`). `js/theme.js` sets light/dark before first paint (`js/app/look.js` after). A skin saved by an older version (web `settings.skin` apple/arch, which older iPhone/Mac apps also write into their web view; the desktop's `"skin"`; the Apple app's `yap.skin`) is ignored and dropped. Windows 98 keeps its instant/stepped motion on purpose, and its title bars stay active on both windows (the focus swap made the sidebar's bar flash).
- **Updates:** web pages update themselves after a deploy (`tools/stamp.mjs` → `web/js/build.js` + `worker/build.ts`, generated by install/dev/check/deploy and never committed; PROTOCOL.md › Updates). Desktop apps: signed click-to-update from `/downloads/latest.json` (`desktop/README.md`).
- **What's new highlights:** `web/changelog.json › highlights` is a curated list (date, emoji, title, text, where) shown at the top of `/changelog` while it's from the past 7 days — add the big things there when you release them.
- **Versioning:** you (Claude) own it. Put user-facing `Changelog: …` lines in commit bodies; `npm run release ["Title"]` picks the next version from commits since the last tag, updates `web/changelog.json` + `package.json`, commits and tags (only from a clean tree); then deploy (release-commit trailers, the clean-worktree deploy and the public snapshot: `private/README.md › Releasing and deploying`).
- Invite key: the main link `https://<server>/#key=<key>`. Worker secret `YAP_KEY` is only the first one: a reset (owner, or `POST /api/admin/main-key`) is kept by the Hub in meta `main_key` (in backups). A wrong or old key still opens a token-only socket, so signed-in devices are never stranded; personal invite links are `yi_…`. PROTOCOL.md › Invite links, Resetting the main link.
- **Mod log** (`mod_log`): who let in/banned/made invites/etc., never message text; everyone can read it (Settings › Owner & mods).
- **Each deployment's settings** live in its own `wrangler.jsonc` (gitignored; template `wrangler.example.jsonc`) and Worker secrets: domain, `PUBLIC_URL`, optional Minecraft status and board (`worker/settings.ts`). Nothing about any one server is in the code.
- **GIFs:** KLIPY picker; Worker secret `KLIPY_KEY` (a free KLIPY app key; Testing mode = 100 requests/hour for the whole server). KLIPY's terms forbid proxying — see PROTOCOL.md › GIFs.
- **Board (optional):** another Worker of the server owner's, bound as `BOARD` and served same-origin at `/board` (SELF_HOSTING.md › A board; `worker/board.ts`, `worker/settings.ts`). Yap draws live pointers over it (`web/js/cursors.js`). Tests use a stand-in board (`test/fixtures/board/`).
- **Features** are specified section by section in `PROTOCOL.md` (Identity: accounts, waiting room, roles; Space; Draw layers; Extras; Screen sharing; Watch together; Voice; Backups…); what protects what is `SECURITY.md`; each place has its own file in `web/js/` (`draw.js`, `watch.js`, `space*.js`, `when.js`).
- **No presence, on purpose:** no online/offline, last seen or member column; sessions are only visible in voice or on a shared view (`visible()` in `worker/attachment.ts`); the member list is a People sheet behind the header button.
- **Privacy page:** `/privacy` (`web/privacy.html`), linked from the sidebar. Update it whenever what's stored or shared changes.

## Read these first
- `PROTOCOL.md` — the wire protocol every client implements (and how voice connects).
- `worker/hub.ts` — the server's Durable Object: lifecycle, the message dispatch, sessions and voice; its features are `worker/hub-*.ts` (Code map below).
- `web/js/voice.js` — WebRTC mesh, Opus SDP tuning; `web/js/gate-worklet.js` — the VAD/PTT gate (audio thread).
- `web/js/app.js` — the web client's entry (boot, `handle()`, `onClick()`); the page's parts are in `web/js/app/`.

## Commands
```sh
npm run dev                      # local server on :8787 (open, no key) with your wrangler.jsonc; stamps the build first;
                                 # signing up needs a PIN_PEPPER: cp .dev.vars.example .dev.vars
npm run dev:test -- --port 8787 --persist-to <scratch dir>   # the test server: test/wrangler.test.jsonc + the stand-in board, keyed (testkey/testadmin)
npm run test:all                 # EVERYTHING, the way to test a change: typecheck, the Node suites, then its own test server for protocol + e2e + a backup → restore round trip; --fast skips the server (all flags: tools/test-all.mjs)
YAP_URL=http://localhost:8787 YAP_KEY=testkey YAP_ADMIN_KEY=testadmin npm test   # protocol test against a running test server
YAP_URL=http://localhost:8787 YAP_KEY=testkey YAP_ADMIN_KEY=testadmin npm run test:e2e -- <shotDir>   # headless Chromiums: chat, real P2P voice, GIF picker (mocked KLIPY), screenshots
npm run deploy                   # stamp + ship to Cloudflare with your wrangler.jsonc; open pages update themselves
node tools/restore.mjs <backup.json.gz> --to <url>   # disaster recovery into an EMPTY server (needs the same PIN_PEPPER)
```
`npm run test:all` sets all of this up itself. By hand, the protocol and e2e suites need the test server started with the `--var` flags that `tools/test-all.mjs` sets (`NTFY_SERVER`, `TEST_HANGS`, `TEST_PINS`, `TEST_OBS_GRACE`, `VAPID_PRIVATE_JWK`) on a fresh `--persist-to`; every suite signs up with the made-up password `correct-horse-582039`.

## Conventions
- Protocol changes: edit `worker/protocol.ts` **and** `PROTOCOL.md` together; bump `PROTOCOL_VERSION` only for breaking changes.
- Client JS: ES modules, no framework, no bundler, no CDN (works offline / embeddable). Escape every user string with `esc()` before `innerHTML`.
- Server state that must survive hibernation goes in the socket attachment (≤ 2 KB) or SQLite — never only in instance fields (`lastTs` is a cache re-derived from SQLite).
- Free-plan budget: 100k requests/day (incoming WebSocket messages count 20:1), 100k row writes/day, 5 GB. Nothing per-audio-frame may touch the server.

## Guardrails
**Production data (real friends' messages):**
- `MIGRATIONS` in `worker/schema.ts` is **append-only**. Never edit a shipped migration; never drop/rename columns. `npm run test:migrations` upgrades databases from every older version.
- **Deleted messages are erased** (2026-10-05: "dont save deleted posts") — that's the one hard delete, and only of what the person deleted. Everything else stays soft (`deleted_at`, `archived_at`); never erase anything else without asking.
- Before changing the schema or any persisted shape, audit every reader/writer in `worker/hub.ts` and `worker/hub-*.ts`.

**Untested surfaces — call out "Please test this manually":**
- Voice across real networks (CGNAT/cellular may need TURN; tests only cover localhost).
- Safari / iOS / Firefox voice (tests run Chromium only), output-device picking, Bluetooth headsets.
- Echo cancellation / noise suppression quality (the desktop's AEC3 was only measured offline and in an echo loop: real speakers on macOS, Windows and Linux), push-to-talk feel, notifications.
- Round 10's feel: the push-to-talk click and double-tap latch, the "You're muted" reminder with a real mic, global keys on each OS and Wayland, `yap --remote` from a Stream Deck, Ctrl/⌘+scroll on rows, Space panning on headphones, the shared-media dip, the own-connection hint on a lossy uplink.
- RED on real lossy networks and Safari/Firefox (measured through the impairment proxy with Chromium only), the call report's clipboard on each OS, the iPhone's Mic mode picker (needs a real call on a device).
- iPhone calls with the screen off (interruptions, route and network changes while locked), iPhone/iPad screen broadcasts (ReplayKit doesn't run in the simulator), the desktop's Apple screen picker, and the call's Live Activity on a phone (its Dynamic Island never shows in simulator screenshots; its buttons from the Lock Screen).

## Decision log
Dated reasons for the big calls (Cloudflare over a VPS, the P2P mesh, passwords, RED, calls that survive reconnects, the OBS link, the one look, MIT…) are in `docs/DECISIONS.md`: read the matching entry before reversing one. Code comments that cite "CLAUDE.md › Decision log" (TD1, TD3, TD9) mean that file.
- **Declined on purpose** (don't re-propose without asking): CallKit / call controls in the Phone app; a guided mic setup; one-time or expiring invite links; Electron and Tauri; Draw layers beyond the three fixed ones; a second look or skin (one look: Windows 98 / AIM); sound in Mac/iPhone screen shares (stasel/WebRTC can't). Search stays a LIKE scan until rows-read matters. The quality picker (up to 510 kbps) stays unless sources prove more than 128/192 kbps is inaudible.
- A deploy without `web/downloads/` (gitignored) deletes the desktop downloads from the site. The v10 board-link seed edit (2026-10-06) was a one-off, not a precedent for editing a shipped migration.

## Code map
- **Hub:** `worker/hub.ts` is the `Hub` Durable Object: lifecycle, the message dispatch, sessions, voice and the Worker's RPC (one-line delegations). Its features are functions of `hub: HubHost` in `hub-*.ts`; `hub-host.ts` says exactly which Hub members they may use (PATTERNS.md › A Durable Object in feature modules).
- **Web:** `web/js/app.js` is the entry (boot, `handle()` for server messages, `bindUi()`, `onClick()`); `web/js/app/` holds the page's parts (`state.js` — state and the socket, a leaf — loads first); `web/js/*.js` are self-contained widgets. PATTERNS.md › The web client's modules.
