# Yap decisions

Why Yap is the way it is: dated decisions, with the maintainer's calls and the numbers behind them. `CLAUDE.md` keeps the standing rules and points here; read the matching entry before reversing a decision.

- **2026-10-21** Rounds 11 + 12 (maintainer: "i dont want any big new features or changes really right now, it works. i want polishes, performance and stability improvements, and suggestions"; then of the suggestions "2-8 do it all", with Apple pushes waiting on his APNs key). Round 11 was fixes only; two additive migrations: v19 indexes `messages.ts` (waking and backups read every message without it), v20 keeps each send's `nonce` (never on the wire, never in backups) so a send repeated after a reconnect is answered with the message it already made instead of stored twice (one index write per message; the window is a day, so a phone locked mid-send is covered). Round 12, the same spec in every app: drafts per channel in memory only (a reload doesn't keep them; an edit or reply never follows you to another channel); "↓ New messages" at the bottom when someone writes while you're scrolled up; the unread-mention count as a badge (installed web app, iPhone icon, Mac Dock, the desktop's Dock on macOS; the desktop also flashes the taskbar / bounces once on a mention); a "You were in {channel}." bar with Rejoin after a reload, crash or relaunch, for 10 minutes, never joining by itself (a click starts audio on the web anyway, and an unasked-for join would be a surprise); Mic volume 0–200 % (web `settings.micVolume`, linear) applied after noise removal and before the gate, bit-identical at 100 %, a soft limiter at −1 dBFS above it, while "Too loud (clipping)" keeps measuring the raw mic (no gain fixes ADC clipping). The iPhone/Mac app can't add a software gain (TD9: no hook on stasel/WebRTC's send path), so its Mic volume is the hardware level where the route allows it (iPhone input gain 0–100 %, the Mac input device's volume), hidden elsewhere. Pushes about a message open that message (`#channel=…&message=…`, the invite key never in it). `watch.queue {remove, id?}`: removing by id, because an index could take out the wrong video when the queue moved up at the same moment (optional field, no version bump).
- **2026-10-18** New icon (maintainer picked "Bubble" from a gallery of open-source packs): Pixelarticons' `message-text` glyph (MIT, credited in README › Credits) in white on a teal gradient (#0b8f8f → #006b6b). `apple/Tools/make-icons.swift` draws every raster icon from its 24-unit grid with a whole number of pixels per cell wherever a cell gets 2.5 px or more (smoothed below that, the Mac's Finder sizes), at 62% of the icon, which also keeps it inside a maskable web icon's safe circle. The iPhone app icon gained dark (teal bubble on near-black) and tinted (light grey) looks. `web/icon.svg` is no longer transparent: it's the same teal tile (one cell = 1 px at 32 px, so the 16 px title-bar icon is crisp on 2x screens), used for the tab, title bars, sign-on and notifications. The desktop draws the same rects in `app_icon()` (72 px, 2 px per cell).
- **2026-10-12** MIT instead of AGPL-3.0 (maintainer: "we're just vibe coding it all anyways"; "switch to MIT for both yes", Questboard too). Checked first: no copied code from AGPL projects (the OBS page took only VDO.Ninja's approach, see `web/js/obs.js`), every dependency is MIT/Apache/BSD-compatible, one author. Copies released before v0.47.1 stay AGPL for whoever has them. The Source link (`SOURCE_URL`) stays, as a courtesy rather than an obligation. The copyright line says **yesokcool**, not his real name, which is on the public blocklist. README and GitHub describe Yap as a "voice and chat app".
- **2026-10-11** Round 10, ideas from a read of Mumble's source (maintainer picked them: "1,2,3,4", "5 = allow ppl to listen to shared media volume for themselves", "6,7 yes", "no to 8 unless you think it's actually a good idea"; then "just do all of it now"). Every app: a "You're muted" reminder (blip + words, at most every 5 s, its own setting), Ctrl/⌘+Shift+M/D, a push-to-talk click and double-tap latch, push-to-mute (nothing on the wire), an own-connection hint from `remote-inbound-rtp` and "From you: they lost X % of yours" in the call report, your volume on voice rows (+ Ctrl/⌘+scroll on computers), an opt-in "Lower shared media while friends talk", Space panning (web + desktop; per-ear gains, not StereoPannerNode, whose middle is −3 dB), "Too loud (clipping)". The desktop also got global mute/deafen/push-to-mute keys (combinations allowed; polled only in a call once set, so no Input Monitoring prompt for people who never use them) and `yap --remote`. No guided mic setup (Test mic and Hear yourself cover it). Quality picker kept (maintainer: remove it only if sources prove >128/192 kbps is physically inaudible; they say "pretty much transparent" at 128 and a few killer samples stay detectable at 160–192), with a warning at 256/510 (no dropout protection, more upload); the "lower of the two" wording was wrong (each sender uses its own setting) and is corrected. Found on the way: the iPhone/Mac app's per-person volume never worked (stasel/WebRTC hands out a new wrapper per call, so `===` never matched); fixed. Space's voice rules (zones, panning) don't reach the iPhone/Mac app, whose Space web view isn't in the call.
- **2026-10-11** OBS link reworked after VDO.Ninja (maintainer: "LOTS of distortion … why don't you just literally copy it", after v0.45.0's 10 ms packets + zero jitter buffer, which were rolled back in v0.45.1). VDO.Ninja's viewer (read at commit 0ac8228, AGPL like Yap): a plain media element, no WebAudio in OBS, the browser's default buffer, no SDP changes, play() again when paused, no silence trick. Measured with the real app in Firefox and Chrome at 510 kbps into the OBS page and a CEF-style capture: clean before and after; no page-side cause found, so the distortion is most likely OBS on Windows itself (the browser source with "Control audio via OBS" stuttering when OBS is minimized or covered, and OBS's own audio buffering). Copied: straight-through playback, browser defaults, resume on pause. Not copied: mono ~32 kbps (Opus voip mode measured further from the original). The keep-alive tone stays, but only in silence: Yap's gate sends digital silence and CEF drops a silent page's capture, while VDO.Ninja's ungated senders keep a noise floor. Open: the "lower of the two" bitrate rule doesn't hold in browsers (each sender uses its own cap), so an OBS link can't ask for less than a sender's 510 kbps.
- **2026-10-11** OBS link: lowest delay (maintainer: "make just the obs link play it more directly"; yes to the shortest jitter buffer like VDO.Ninja; his use: in the call on his Mac, recording on his Windows PC). Straight through + jitter target 0 + 10 ms packets (the part that measurably helps, ~10 ms); RED kept (no measurable delay). The glitch at the first words after a pause (heard only in OBS) was OBS's browser (CEF) stopping its capture once Chromium calls the page silent: fixed with an inaudible hum. About 1 s of the 2 s he first saw was OBS's own audio buffering after Windows swapped his output device (restart OBS, pin Desktop Audio).
- **2026-10-11** Round 7 (maintainer: "we should also have a way to reset main link. with a pop up warning"; an OBS link left running while he's out of the call should show him greyed out "so ppl know" and stop after 5 minutes; "yes do the noise suppression fix"; Test mic "doesnt seem to do anything"). The server keeps a reset key itself (a meta row, no migration); a wrong or old key still opens a socket that may only present a device token, so nobody signed in is stranded and only newcomers need the new link. The cost: outsiders without the key now reach the Durable Object (a socket that closes), so the WAF rule matters more. OBS links listen only where their account is, or for 5 minutes after (the server's alarm enforces it), shown greyed meanwhile. The web has one Noise suppression switch using RNNoise wherever it runs. Test mic is a toggle that says what it hears (it gave no sign of working, and could get stuck). Earlier the same day the OBS link was hidden outright (maintainer: "obs can already record whatever without anyone knowing"); the greyed row is his refinement.
- **2026-10-11** Passwords instead of PINs, and only the owner and mods let people in (maintainer: "yes do passwords instead of pins and do all of that stuff"; "yes only me and mods should be able to let people in"). Having both confused people (a refused "dog123", a board asking for "your Yap password", PIN resets). New accounts and changes need 8+ characters; the most common passwords (SecLists, ~10,800, 100 KB in the Worker), your own name, repeats and keyboard/number runs are refused. Existing PINs keep signing in until their owner sets a password, so nobody is locked out; they're asked once per device, never nagged, and a wrong sign-in says an old PIN works there. Resets hand out a temporary password (three words + two digits) that asks to be replaced (`users.weak_secret = 2`, no migration). No "password again" field: Show/Hide instead. The wire keeps its `pin` names so older apps keep working. Only the owner and mods see the waiting room and let people in, with a push; members meet newcomers through `join.resolved.user`. Not wanted: one-time/expiring invite links. The desktop app stays next to the Mac app (downloads with push-to-talk for everyone; TestFlight is the maintainer's phone channel). Supersedes 2026-10-05 "Account protection instead of a switch to passwords".
- **2026-10-11** Round 5 (maintainer: "what else can we do to make the audio and call as stable and high quality and good as possible"; offered five, answered "do it all"; the voice relay is his sign-up). Every voice packet carries the frame before it (RED, RFC 2198, PROTOCOL › Voice › Redundancy), negotiated so older apps stay on plain Opus. Measured through the impairment proxy at 128 kbps, audio patched over fell about tenfold on every client (web↔web, iPhone↔web, desktop↔web: cellular-like ~4–5 % → 0.3–0.5 %) for twice the upload (~260 kbps per person you talk to; Opus itself stays at the setting). At 256/510 kbps the copy never fits 1200 bytes, so those calls get no RED: accepted, since 128 kbps is the default and already transparent for voice. Each app keeps a call report on the device (Copy call report / Copy last call report; no IPs, no messages) so a call that sounded off can be looked into. The desktop got echo cancellation (WebRTC's AEC3 through the pure-Rust `sonora`, because the C++ library needs meson/abseil and wouldn't cross-build): ~50–56 dB of echo removed offline, on by default like the web's, ~0.5 % of a core; the Linux binary stays under the 25 MiB asset limit by moving once-per-call crates (DTLS, SCTP, SDP, mDNS) to opt-level "s". The iPhone got a Mic mode row that opens Apple's Voice Isolation picker (not on the Mac: its calls don't use Apple's voice processing). No CallKit (maintainer: doesn't want call controls).
- **2026-10-11** Round 4 (maintainer: "yes to [the] decisions"; "sometimes i got dropped from calls, usually when phone screen went off"). iPhone calls keep a receive-only audio anchor for the whole call: WebRTC let the audio session go whenever its last stream changed (someone joining while you're alone, the last one leaving, a rebuild), and iOS then suspended Yap. What Yap still can't prevent (a long interruption, 60 s offline, iOS stopping it) ends the call for real with a "You left <channel>" notification, tap to rejoin; no ghost in the channel. iPhone/iPad share through a broadcast extension that only scales and hands pictures to the app (no encoding in the extension, 50 MB limit). The desktop on macOS 14+ shares through Apple's picker; the picked stream lives for the whole share (idle at 1 fps, so the purple indicator stays) so macOS asks once. A send the server turns away goes again (slow_down) or comes back to the message box, the same in every client (PROTOCOL › Identity). Not done, on purpose: CallKit (calls in the Phone app's Recents; the maintainer doesn't want call controls), sound in Mac/iPhone shares.
- **2026-10-10** One look: Windows 98 in light or dark, in every client (maintainer: "considering to remove apple and arch skins to simplify app and i dont think we need it"; asked, chose removing them everywhere). Every feature now gets built once per client instead of three times. A stored Apple/Arch choice silently becomes Windows 98 and keeps light/dark. Same day, screen sharing in every app and better (maintainer: "implement screen sharing in the native apps and please make it better"): the web is the reference for behaviour and words; H.264 constrained baseline (packetization-mode=1) is the codec every client offers, so the web never drops it; viewers find a screen from what was negotiated, not from stream ids. No wire changes. And someone's volume opens from their row under a voice channel in every app, like the web (maintainer: "native app i cant set volume for other users").
- **2026-10-08** Four small calls from the second polish pass (maintainer: "you decide all"). Away messages end the same way everywhere: until my next message, 1 hour, 3 hours, tomorrow morning (9:00) — the web's and desktop's set; the iPhone/Mac app dropped "4 hours" and "tonight". The iPhone/Mac app's Apple skin keeps the system's confirmation dialogs (looking native is that skin's point; the web's Apple skin draws its own only because a page can't use the system's). The desktop app keeps [OK] [Cancel] in every dialog (Windows' own order, and consistent within the app) rather than flipping to the web's. The desktop waiting room keeps "Use a different invite link…" without a separate "Start over" (a polish pass adds no controls). *(The Apple-skin part is superseded 2026-10-10: one look.)*
- **2026-10-06** All three clients now keep calls across reconnects, gate the same way and restart ICE after 3.5 s `disconnected` (the iPhone/Mac app and the desktop adopted PROTOCOL.md › Voice after the web). Two known differences, both forced by the stack: the Apple app has no 40 ms pre-roll or fades (the WebRTC SDK has no hook on the send path; only a custom audio device would, TD9), and its level comes from WebRTC's energy stats, which are per-frame peak, so it subtracts 9 dB to match the web's RMS scale (an old Apple sensitivity setting moves down with it; the −50 default stays). The Mac app doesn't follow a new default mic mid-call; the silence warning covers it.
- **2026-10-06** The desktop's jitter buffer aims at the 99th percentile of how late packets arrive, plus 10 ms, clamped to 40–200 ms, with a 60 ms floor while packets are being lost (Chrome sits at 55–60 ms) so FEC's next packet is there in time. The audit planned p95, but p95 still left 2.6 % of audio repaired on a Wi‑Fi-like network. p99 brings it to ~1.9 % (cell-like 12.7 % → ~4 %), at the cost of ~145–160 ms held on a jittery network (25–45 ms on a clean one). Drift is fixed one frame at a time during quiet audio, never by jumping.
- **2026-10-06** Calls survive reconnects (TD1, maintainer: yes). Every deploy dropped every socket, which hung up every call (0.6–0.7 s of silence and a burst of leave/join chimes for everyone). Now a client that drops keeps its peer connections, rejoins with `prev` + a proof, and everyone moves the same connection to its new session id: no gap, no chimes. The proof is an HMAC of (sid, uid) with a secret the server keeps, not a table of old sessions: after a deploy the server remembers nothing, and the proof still says "this was your session". Opt-in per pair (`resume` in `voice.join`), so the shipped desktop 0.8.0 and iPhone apps see exactly the old messages and keep working; they can adopt it later from PROTOCOL.md alone. Not done: holding back the server's leave broadcast (that would change what older apps see).
- **2026-10-06** Voice-activity pre-roll (TD3, maintainer: yes): in voice-activity mode only, the web sends audio 40 ms late so the gate opens *before* the first syllable (it used to clip 20–50 ms, more on a busy page; measured on the real gate code: ~0 ms). The cost is 40 ms more mouth-to-ear delay, so never in push-to-talk or always-on, where nothing needs predicting. Picked 40 over 30 because soft starts in a noisy room still clipped at 30 (p90 12 ms vs 2 ms). The gate moved onto the audio thread at the same time (hysteresis, 450 ms hold, fades, a 200 ms push-to-talk tail, an adaptive noise floor), specified in PROTOCOL.md › Voice so the native apps can match it.
- **2026-10-06** The one exception to "never edit a shipped migration": v10's board-link seed carried the first server's own board name and address, so it now seeds a plain "Board" with no address (the maintainer said yes). Changing seed text only affects brand-new servers; servers that already ran v10 keep their row. `BOARD_NAME` renames the link (there's no rename in the app), and an empty address means this server's `/board`. Don't take this as a precedent for schema changes.
- **2026-10-06** Draw layers (maintainer: "add draw layers sure", after first declining them). Three fixed layers shared by everyone, not add/remove/reorder/rename: on a live shared page, structural layer edits would fight between people, and three covers sketch → colour → ink. Which layer you're on and which you've hidden stay on your device; only strokes (with `l`) and a whole-layer wipe go over the wire. Exports are what you see, so hiding the sketch layer gives a clean picture; Clear/wipe archives always keep everything.
- **2026-10-06** Thirteen extras in one go (the maintainer picked "all" from a pitch; "be sure to add a volume limit to soundboard"). Calm versions on purpose: away messages only show in context (People, a mention's auto-reply), never as a dot; "Since you left" is a divider and a list you open, never a popup; quiet hours live on the server so every push path respects them. The soundboard can't be loud: WAV only so the Worker can measure each clip and cap its gain, then every client multiplies by your own volume and runs a limiter. Dice are rolled server-side so a roll proves something. Draw layers were offered and declined ("this is just simple drawing on 1 layer"), then added the same day (the entry above).
- **2026-10-05** Search is a plain LIKE scan (no FTS5): friend-group scale, zero migration risk; revisit if rows-read on the free plan ever matters.
- **2026-10-05** No presence (maintainer: "get rid of online/offline indicators for users completely… ppl should be able to get on here and chill"). Enforced on the server, not just hidden: idle sessions aren't sent at all; voice/views still need sessions, so those appear only while in use. The member column became an on-demand People sheet.
- **2026-10-05** Deleted posts are erased, not soft-deleted (maintainer: "dont save deleted posts"); posts deleted before then were erased by migration v15. Tombstone rows stay so ids/replies keep working. Picture edge cache dropped to 1 day for `/media/`.
- **2026-10-05** Message limit 4,000 → 40,000 characters (maintainer: "there should not be a text limit… or at least make it bigger"). Bounded by the 384 KB frame cap; history pages stop at ~512 KB; clients fold long messages.
- **2026-10-05** Encrypted Personal space: passcode-wrapped random key (PBKDF2 600k + AES-GCM), not a key derived straight from the PIN — the PIN is only 6 digits and the server checks it, so it can't double as an encryption secret. Each device keeps a non-extractable key; changing the passcode re-wraps without re-encrypting.
- **2026-10-05** When's good stores absolute half-hour slots (not "Tuesday 8 PM"), so friends in different time zones agree; "clears every week" = only this and next week are shown/kept.
- **2026-10-05** Redesign #2: Windows 98 / AIM (maintainer: "Yap OS" read "more as a wannabe retro video game reskin rather than a real old school simple clear but truly nostalgic design"; Win98/AIM won over Mac OS 9 and XP/MSN). Real period chrome, no pixel fonts. Profile card opens Settings › Profile; Mute/Deafen are big labelled toggles (his ask: "better than Discord").
- **2026-10-05** Live updates without a refresh: build hash in `ready` (and a `build` message for sockets that survive a deploy). Reload only at a quiet moment (no voice, empty composer, nothing still sending, no dialog, tab hidden or idle 5 min); otherwise an info bar with "Restart now". No polling: deploys drop sockets anyway, so it costs nothing. wrangler dev keeps sockets across reloads, so locally the new code only announces itself when something wakes the Hub.
- **2026-10-05** Desktop self-update: static `/downloads/latest.json` + Ed25519-signed binaries (the private key stays with whoever publishes; the public key is compiled in at build time), install on click only. Static assets cost no Worker requests; 25 MiB per-file limit fits the ~15–18 MB binaries. `web/downloads/` is gitignored, so deploy from the machine that holds it (a deploy without it would delete the downloads).
- **2026-10-04** Cloudflare Workers + Durable Objects over a VPS: free *and* always-on with no box to babysit; Oracle's free VM was the alternative (UDP, but signup friction + idle reclamation).
- **2026-10-04** WebRTC P2P mesh over a server relay (Mumble-style): relaying audio through the Durable Object would blow the free-plan request budget in hours; P2P makes bitrate free. Trade-off: each person uploads one stream per peer (fine for ~2–8 people). An SFU (Cloudflare Realtime, 1 TB/mo free) is the scale-up path.
- **2026-10-04** Opus via SDP fmtp tuning: default 128 kbps (Discord: 64 default, 96 max unboosted), FEC on, DTX off, stereo-capable; measured 129 kbps in the headless test.
- **2026-10-04** Native desktop instead of Electron (maintainer: "electron is actual garbage"). Tauri ruled out: Linux WebKitGTK WebRTC is unreliable. One Rust client for Windows, Linux and macOS.
- **2026-10-05** GIFs via KLIPY (Tenor's API died 2026-06-30; Giphy's free tier is 100/hr with paid production). Message gets an optional `gif` field (migration v2) rather than "URL in the body", so clients know the size up front (no layout jump) and the server can allowlist KLIPY's CDN (no IP-logging images).
- **2026-10-05** Custom emojis: Discord-style `<:name:id>` tokens with content-hash ids (renames/deletes never break history; images immutable → cached forever). Images live in a second Durable Object (`Media`) so they can't crowd out messages; R2 was the alternative but needs a billing method on the account.
- **2026-10-05** Backups = Cloudflare PITR (30 days, in place) + daily full export pulled to the maintainer's own machine (off-Cloudflare). No "offload at threshold": text is ~250 B/message, so the 1 GB chat DB holds ~4M messages; `/api/admin/stats` + the backup log show usage.
- **2026-10-05** Real accounts = name + 6-digit PIN + per-device tokens (a member couldn't get back in on a new device; uid-only identity also let members impersonate). PIN over password because it's friendlier and the online lockout (5 tries, then doubling waits) is what actually protects it. Pre-PIN devices keep working until they set a PIN; device links removed. *(The pre-PIN part was superseded 2026-10-06.)*
- **2026-10-05** A board (the maintainer's group's game board) folded into Yap as a same-origin view (service binding proxy) instead of a rewrite or a cross-origin iframe: zero changes to the board's code, and same-origin lets Yap draw pointers over it. Pointers anchor to cards/columns, not pixels, because everyone's layout differs. **2026-10-06:** the board itself moved to its own repo; Yap keeps the optional hook (`BOARD`).
- **2026-10-05** *(Since 2026-10-11 only the owner and mods let people in.)* Waiting room over captchas/accounts: the invite link keeps randoms out; if it leaks, strangers still can't see or post anything until a member lets them in. Ban + delete-any for owner/mods; rate limits per session.
- **2026-10-05** Unique display names + mergeable accounts (`user_aliases`, read-time mapping, nothing rewritten) + device links. Duplicates came from new browsers/addresses minting new uids. (Since then: real accounts with PINs, below.)
- **2026-10-05** Custom domain, `workers_dev` off: the workers.dev subdomain is the Cloudflare account's name, which is often the owner's email username. Changing origin resets everyone's local settings (localStorage is per-origin), so pick the domain early.
- **2026-10-05** Message list renders by key (`nodeFor`/`reconcile`, now in `web/js/app/messages.js`), not `innerHTML` of the whole list, so playing GIFs don't restart on every new message.
